Z-View 待改善项清单
🔴 P0：优先处理，涉及安全或大规模故障风险
编号	问题	当前情况	改进方向
P0-01	Agent 全局共用 Token	84 台 Agent 共用一个 agent_token	改为一机一密，建立 agent_id + device_secret
P0-02	Agent → 平台明文 HTTP	内网 HTTP，依赖部署环境保证安全	Agent API 全部 HTTPS，长期采用 mTLS
P0-03	Named Pipe fail-open	IPC 会话校验存在 fail-open	改为 fail-closed，失败必须拒绝
P0-04	SYSTEM Helper 权限边界	Helper 可以抓屏、SendInput、操作安全桌面	强化 Pipe ACL、Session/PID/Token 校验
P0-05	Agent 升级仅 SHA256	SHA256 只能验证完整性	增加 Authenticode/数字签名验证
P0-06	升级失败风险	Agent 自替换涉及 stop/kill/replace/start	增加升级状态机、失败回滚、升级锁、健康检查
P0-07	远控权限控制	Remote Session 权限链路较复杂	明确 RBAC + Session TTL + revoke + 审计
P0-08	自研认证协议风险	HMAC Token、PBKDF2、自定义 Token	收敛认证模型，减少自定义协议逻辑
P0-09	生产密钥管理	.env/文件保存密钥	密钥权限隔离、轮换、最小权限；生产环境考虑 Secret Store
P0-10	高权限命令执行	Agent SYSTEM 执行 shell/security command	建立严格命令白名单、参数校验、审计和超时
其中我认为最重要的是：
Agent 全局 Token

        ↓
SYSTEM Helper
        ↓
远程命令 / SendInput

这几个组合起来，属于真正需要做安全审计的区域。
