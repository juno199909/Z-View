### 4. Agent TLS 缓存钉死故障：服务端证书变更后 Agent 无法自愈
- **状态**：[x] 已完成（2026-09-20）
- **位置**：`zvagent/auth.py`（`_platform_base`）、`zvagent/heartbeat.py`
- **现象**：Agent 的 TLS 自动协商一旦探测 HTTPS 成功并缓存 `tls_ok=true`（24h），后续即使服务端证书变更导致 SSL 验证失败，Agent 也不会降级回 HTTP，会一直心跳失败直到自愈合退出重启
- **根本原因**：
  1. 正向缓存 24h 内直接用 HTTPS，不再探测
  2. 心跳 SSL 错误没有触发缓存失效
  3. 验证失败和连接失败的回退时间一样（10min），证书不匹配的场景重试没意义
- **修复内容**：
  1. `_platform_base()` 增加 `fail_ttl` 机制：SSL/cert 验证失败缓存 1h，连接失败缓存 10min
  2. 新增 `invalidate_tls_cache()` 函数：强制清除 TLS 缓存触发重新探测
  3. `get_asset_id_from_server()` 和主心跳循环的异常处理中：检测到 SSL 错误时调用 `invalidate_tls_cache()`
- **验证**：
  - `invalidate_tls_cache()` 正常删除缓存文件
  - 语法检查通过；Agent 认证单元测试 7/7 通过
  - DESKTOP-JEGI046 机器删除 TLS 缓存后已恢复上线

### 1.9.52 坏版本事故：构建缺 `__version__`，全员 Agent 启动即崩
- **状态**：[x] 已完成（1.9.53 修复发布）
- **现象**：`zvagent/__init__.py` 中 `__version__ = "1.9.52"` 与注释粘成一行，名字未定义；所有 1.9.52 终端的用户会话 Agent 启动即抛 `ImportError: cannot import name '__version__'`
- **修复**：重写 `__init__.py`（版本号独立成行）→ 1.9.53 重建发布，updater 自动滚动恢复（服务端机器 1 分钟自愈）
- **预防**：发布前必须 `python -c "import zvagent; print(zvagent.__version__)"` 自检；该文件曾是 GBK/UTF-8 双重乱码，手工编辑易吞换行
- **位置**：`zvagent/__init__.py`

### 托盘「退出代理」假退出（控制台永远在线）
- **状态**：[x] 已完成（1.9.54）
- **现象**：右键退出只 `DestroyWindow` 杀托盘自身，服务/会话进程照常心跳 → 控制台永远 online
- **修复**：确认框 → UAC 提权拉起 `--stop-agent`（sc stop + 等真正 STOPPED + 清会话残留）；心跳停止后控制台 90s 内离线；UAC 取消则托盘保持驻留
- **位置**：`cmdb_agent_consent_ui.py`、`cmdb_agent_unified_v2.run_stop_agent`

### Agent 自安装：对运行中目录重装即损坏 + `sc start` 阻塞崩溃
- **状态**：[x] 已完成（1.9.53/1.9.54）
- **现象**：同版本重装对运行中的 `versions\<ver>` 做 rmtree+copytree → `_internal` 拷坏（jaraco `Lorem ipsum.txt` 缺失）→ 服务 import 断裂、永远不上报 RUNNING（SCM StartPending 挂死）；另 `sc start` 阻塞 120s 的 TimeoutExpired 未捕获，直接崩掉整个自安装

- **位置**：`cmdb_agent_unified_v2.run_self_install`
