# 终端概览分组功能修复说明

**修复时间**: 2026-06-11 16:20  
**问题**: 分组修改后刷新页面丢失  
**状态**: ✅ 已修复

---

## 🐛 问题描述

### 问题现象
1. 在终端概览中修改终端的分组
2. 提示"分组更新成功"
3. 刷新页面后，分组又恢复成原来的值

### 根本原因
分组更新成功后，**没有重新加载数据**，导致：
- 前端显示的是修改后的值（临时的）
- 但没有从服务器获取最新数据
- 刷新页面时重新从服务器加载，显示了修改前的值

**实际上数据库中已经更新成功了**，只是前端没有刷新显示。

---

## ✅ 解决方案

### 修改前
```javascript
const handleGroupChange = async (row) => {
  try {
    await updateAsset(row.id, {
      group_id: row.group_id || null
    })
    ElMessage.success('分组更新成功')
    // ❌ 没有重新加载数据
  } catch (error) {
    ElMessage.error('分组更新失败')
    loadData()  // 只在失败时加载
  }
}
```

### 修改后
```javascript
const handleGroupChange = async (row) => {
  try {
    await updateAsset(row.id, {
      group_id: row.group_id || null
    })
    ElMessage.success('分组更新成功')
    await loadData()  // ✅ 成功后重新加载
  } catch (error) {
    ElMessage.error('分组更新失败')
    await loadData()  // ✅ 失败也加载，恢复原值
  }
}
```

### 为什么这样修改

1. **成功时重新加载**
   - 从服务器获取最新数据
   - 确保前端显示与数据库一致
   - 刷新页面时不会丢失

2. **失败时也重新加载**
   - 恢复数据库中的原始值
   - 避免前端显示错误的值

## 🔍 技术细节

### 前端实现

**数据绑定**:
```vue
<el-select 
  v-model="row.group_id"
  @change="handleGroupChange(row)"
>
```

**更新逻辑**:
```javascript
1. 用户选择新分组
2. 触发 @change 事件
3. 调用 handleGroupChange(row)
4. 发送API请求 updateAsset(id, {group_id})
5. 成功后重新加载数据 loadData()
6. 列表更新，显示最新数据
```

### 后端接口

**接口**: `PUT /api/v1/assets/{id}`

**请求体**:
```json
{
  "group_id": 1  // 或 null 表示清空
}
```

**响应**:
```json
{
  "message": "Asset updated successfully"
}
```

**特点**:
- ✅ 支持部分更新（只更新group_id）
- ✅ 支持null值（清空分组）
- ✅ 自动更新updated_at时间戳
