## 一、项目概述

### 1.1 定位

**面向企业 IT 运维场景的终端管理与远程运维平台**，从「资产管理 + 远程桌面」扩展出终端安全管理能力：

```text
资产管理 + 远程运维 + 终端安全管控（基础能力）+ 安全事件管理 + 集中策略管理
```

功能设计参考企业终端安全产品，当前实现覆盖**基础终端安全管控能力**（存储类 USB 管控、进程黑名单告警、文件完整性监控、防火墙规则下发）；设备级 USB 控制、实时拦截、内核级应用控制属后续路线（见第十三章）。

## 三、认证与 RBAC

- **用户令牌**：HMAC-SHA256 自包含 token，`token_version` 修改密码即失效全部旧 token（实测验证）。
- **密码**：PBKDF2；强度校验；首登强制改密。
- **RBAC**：admin/operator/viewer × 20+ 权限点，`resolve_required_permission` 按路径映射；viewer 只读。
- **Agent 鉴权**：单一 `agent_token` Bearer（hmac.compare_digest）。**已知局限：全网共用 token，未一机一密**（迁移方案见第十三章 R3）。
- **远控授权**：一次性短期 session_token（256-bit 熵），绑定 session_id+asset_id，**DB 只存 SHA256(token)**（P0-4 整改），断开即失效。

## 五、Agent 架构

### 5.1 进程拓扑

```text
CMDB-Agent 服务 (Session 0, LocalSystem)
  └ ServiceRuntime/SessionManager
      ├ WTS 枚举会话 → UserSessionAgent（Session N, 登录用户身份）
      │    ├ :9000 远控 WS    ├ :9001 控制 HTTP
      │    └ 心跳/清单/安全策略同步(300s)/软件任务轮询(30s)
      └ HighIntegrityHelper（Session N, SYSTEM）
           ├ capture worker / input worker（SendInput）
           └ 管道 \\.\pipe\CMDB-Agent-Privileged-Session-{id}
```

### 5.2 管道安全边界（P0-5 整改后现状）

- 消息白名单 6 种：ping / describe_desktop_context / capture_frame / inject_mouse_event / inject_keyboard_event / release_input_state。**无任意命令执行**。
- **DACL**：helper 管道已收紧为 SYSTEM + Administrators + 会话登录用户（`build_session_scoped_pipe_security_attributes`，替代 Everyone）。
- **客户端会话校验**：`GetNamedPipeClientSessionId` 不匹配即断开；**实测 pywin32 在部分环境返回 0，已实现 fail-open + 告警日志**（残余风险：同会话内进程仍可连接——Windows 同用户进程无 OS 级隔离，属平台局限）。
- ServiceRuntime 主管道（CMDB-Agent-Privileged）暂保留宽松 DACL（客户端跨会话），风险登记 R4。

### 6.6 策略解析算法（Policy Resolution Algorithm）

实现于 `agent_get_security_policies`（assets_api）：

```text
1. 收集 enabled 策略中绑定到该 asset 的：global ∪ group(asset 所属) ∪ asset 直绑
2. 按 policy_type 分组，每组取排序后第一条：
   ORDER BY priority DESC → scope(asset=3 > group=2 > global=1) DESC → policy id DESC
   （tie-breaker 为本次整改新增，消除同优先级未定义行为）
3. 语义 =「最具体范围 + 最高优先级 + 最新创建」的单条策略生效（last-match-wins）
4. Disabled 策略不参与（WHERE enabled=TRUE）
5. 撤销 Asset 覆盖 = 删除对应 binding
冲突场景判定：
  Global Allow / Group Block / Asset Allow → Asset 绑定存在则 Allow；
  Asset 无绑定则 Group Block 生效
  同 Asset 属双 Group → priority 高者胜；同 priority → id 大（后建）胜（确定性）
  注意：这是"取一"语义，非 deny-override 合并；多类型（防火墙+USB）间互不影响
```

### 6.7 远程桌面（二进制帧协议 v1）✅核心链路已验证

**协议**：控制消息 text JSON（session_start/screen_info/settings/mouse/key/session_close，protocol_version:1）；屏幕帧 binary：`[1B type][4B frameId][4B width][4B height][4B jpegLen][jpeg]`。

**链路**：Canvas ◀binary WS▶ :8080（session_token=SHA256 存库、断开失效）◀透传▶ Agent:9000。会话生命周期 created→connecting→connected→disconnected 全程审计。

**捕获**：mss/GDI BitBlt（~26ms/帧）+ BILINEAR 缩放 + JPEG（optimize=False，17ms）→ 二进制帧。**DXGI 在 VMware/RDP 环境不可用**。

**DWM 唤醒双机制**（headless/VM 下 DWM 不主动合成）：RedrawWindow@80ms（后台专用线程，产新像素）+ 1px 分层窗口 alpha pulse@33ms（促合成）。

**输入**：归一化坐标 → SendInput（helper SYSTEM 注入，支持 UAC 安全桌面策略）；move 合并。

**帧率实测与机理**：

| 场景 | 帧率 | 机理 |
|---|---|---|
| 被控桌面内容静止 | 1.2 帧/s 变化帧 | **信息论限制**：像素不变即无新帧（RedrawWindow 82 次实测仅 1.2/s 变化——RDP 显示驱动只在真实 UI 变化时更新位图） |
| 内容真实变化（操作/滚动/动画） | 受抓帧 26ms + 编码 17ms 限制，**约 15-23 fps** | 同步流水线上限 |
| 理论上限 | 同步路径 ~40fps（BitBlt 25ms）；60fps 需 DXGI | 异步流水线（Capture∥Encode∥Send）待实现 |

> 校准：v1.0 报告的"13.6fps"为特定 console 会话+显示驱动组合下的测量值；帧率随被控端显示驱动与会话类型波动（1.2~13.6fps），**内容变化时上限 15-23fps（同步路径）**。RustDesk 同样只在变化时发帧。
